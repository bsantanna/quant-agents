What is MCP

Model Context Protocol is the wire format that lets an AI host (Claude Code, Claude Cowork, Hermes Agent, Cursor, and others) discover and call capabilities published by an external server. The official specification defines three server-side primitives:

Primitive Purpose
Tools Executable functions an AI can invoke to perform actions — API calls, queries, computations.
Resources Data sources that provide contextual information by URI — file contents, database rows, prompt templates.
Prompts Reusable templates that structure interactions with the language model.
How the protocol works

MCP runs over JSON-RPC 2.0. After a client connects, both sides negotiate capabilities through an initialize handshake, then the client discovers what's available via tools/list, resources/list, and prompts/list. Quaks uses the Streamable HTTP transport with OAuth 2.1 + PKCE, which is the same model the protocol recommends for remote servers.

Three ways to load a Quaks prompt

Each workflow prompt is registered with the MCP server in three parallel forms so it reaches every client, even the ones that don't surface prompts or resources as first-class objects:

  1. As an MCP Prompt — surfaced by prompts/list and selectable in prompt-aware clients.
  2. As an MCP Resource at the URI prompt://<name> — readable by clients that support resource browsing.
  3. As an argument to the universal read_prompt_mcp tool — the guaranteed-callable fallback for clients that only know how to invoke tools. Skills use this form so the same workflow runs everywhere.

What is a Skill

A Skill is a packaged recipe that teaches an AI agent how to perform a specific task end-to-end. Instead of writing out every instruction by hand, you trigger the skill — and the agent follows a proven sequence of prompts and tool calls to deliver a polished result. Think of it like a saved playbook: the same request produces the same quality of work every time, whether you're asking for a market briefing, a stock analysis, or a portfolio review.

How skills and MCP work together

MCP and skills solve two different problems. MCP gives the agent access — a live connection to Quaks data and operations. A skill gives the agent know-how — the workflow that turns that access into a useful answer. They're complementary: a skill with no MCP has nothing to call, and MCP with no skill leaves the agent to improvise the workflow each time.

Customize prompts in the web UI

Every workflow ships with a default prompt template, but each Quaks account can override any step from the web app. Changes propagate to the MCP server on the next call — no plugin update, no client restart, no redeploy.

  1. Open /insights/agents, pick the analyst you want to customize, and step through the configuration wizard.
  2. Edit the system prompt for any pipeline step (coordinator, aggregator, reporter, fundamental analyst, etc.). Save when you're happy with the wording.
  3. Run the skill again from your MCP client. The MCP server reads your tenant-scoped template and serves it back through the prompts/get, resources/read, and read_prompt_mcp surfaces — your version is now live everywhere the skill is used.
How the live sync works

Every MCP call is resolved per request against the authenticated user's tenant schema. The server first looks for a customized prompt belonging to the calling user; if it finds one, that template is returned verbatim. If the user hasn't customized that step (or isn't signed in), the bundled default is returned instead.

Because the lookup happens at call time, there is no cache to invalidate and nothing to push: saving a prompt in /insights/agents updates the row that the MCP handler is about to read.
